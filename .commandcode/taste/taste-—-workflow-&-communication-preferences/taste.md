# Taste — Workflow & Communication Preferences
- Prefers incremental, phased development on top of existing working code — never recreate or rewrite the project from scratch; inspect the whole project before editing and avoid overwriting working code unnecessarily. Confidence: 0.85
- Requires an approval gate before starting each major phase, and expects the agent to stop and ask before any decision affecting data integrity, privacy, cost, architecture, or irreversible operations. Confidence: 0.85
- Insists on honest verification: never claim a feature works unless it was actually tested, and build/test after each logical change. Confidence: 0.9
- Wants plain-English phase summaries covering files changed, tests performed, risks, results, and how the user can test the change. Confidence: 0.8
- Wants a safe source-control checkpoint (e.g. git commit) before each major phase, with no destructive resets of the repository or the user's data. Confidence: 0.85
- Security/privacy conscious: no secrets, OAuth tokens, passwords, or private keys in source, logs, or APKs; request the minimum permissions and keep sensitive data out of production logs. Confidence: 0.85
- Avoids paid APIs and premature monetization, ads, or analytics; wants cost and privacy implications explained before such services are added. Confidence: 0.8
- Prefers stable, compatible dependency versions and verifying compatibility before upgrading anything. Confidence: 0.75
- Prefers work be broken into small steps rather than implementing several major phases at once. Confidence: 0.8
- Expects Git commits to be authored under his own name (almamun), not the machine's default/global Git identity, and corrects authorship rather than accepting the preconfigured identity. Confidence: 0.65
- Prefers to run Git/config commands that change identity or repository settings himself rather than letting the agent execute them; when such a command is denied, hand over the exact commands and carry on with the steps that don't need them. Confidence: 0.7
- Wants version control backed by a remote GitHub repository on his own account (Al-mamun96), and supplies the remote URL expecting the agent to wire up `origin` and prepare the branch for pushing. Confidence: 0.6
- Treats pushing to a remote as a shared-state action that requires his explicit go-ahead — the agent should stop after committing (or preparing the branch) rather than pushing on its own, and only pushes when he says so. Confidence: 0.75
- Communicates decisions tersely: short single-word directives (e.g. "continue", "commit", "push") or a bare letter selecting one of the agent's offered options (e.g. just "a"), expecting the agent to act on it without needing elaboration. Confidence: 0.75
- Expects a one-line instruction to chain multiple actions: a terse "commit push then continue" means commit, push, and immediately start the next planned step in the same turn rather than pausing after each action. Confidence: 0.65
- When the agent presents numbered/lettered options with a recommendation, he tends to take the recommended path rather than supplying his own alternative input (e.g. accepting the agent's proposed localized labels instead of writing his own, and answering a multi-question prompt with "both recommended"). Confidence: 0.7
- Verifies changes by running the app himself on a real physical Android device through Android Studio, not just via automated tests — expects the agent to help set up the device run (install, logcat, what to check) and to flag manual-only risks like data migrations. Confidence: 0.6
- Communicates in Bengali and romanized Bengali/Banglish mixed freely in the same message (e.g. "r ki ki baki ache"), and is comfortable with the agent replying in Bengali, including a Bengali/English mix. Confidence: 0.7
- Prefers offline-first, on-device processing over cloud services: chose a fully offline rule-based parser over a cloud AI API to keep cost at zero, avoid adding network permissions, and keep his data on the phone. Confidence: 0.7
- Prefers to avoid building or paying for backend infrastructure — picked syncing to his own Google Sheet over a custom server/backend to dodge hosting cost and maintenance. Confidence: 0.6
- For financial data, favours correctness over speed: prefers the app echo back what it understood and get an explicit confirmation before committing a record, rather than saving a possible misread silently. Confidence: 0.6
- Keeps raw exception/internal text out of the UI: report failures to the user by the exception's class name (or an equivalent short, stable token) rather than `localizedMessage`, so SQLite/platform internals (constraint, table, column names) never appear on screen. Confidence: 0.6
- Likes tests named as plain-English statements of the behaviour being pinned (including named "the case that mattered" regression tests) with assertion messages that say why the failure matters, so a regression fails loudly with its reason instead of silently passing. Confidence: 0.65
- Wants input kept to free text only: expects to just type a sentence and have the app infer everything (type, category, dates, cash-vs-credit) itself, and resists any design that adds forms, pickers, or steps that make him choose manually. Confidence: 0.65
